# 手柄遥控、蓝牙与输入诊断

[文档索引](README.md) · [操作与安全](USAGE.md) · [调度与超时](ARCHITECTURE.md) · [验证记录](VALIDATION.md)

WinMM只读诊断、桌面手柄采集和经典蓝牙SPP直连均为**Windows-only**。便携网页使用Web Serial及浏览器真实Gamepad API，不支持WinMM或经典RFCOMM；Web Bluetooth/BLE不是HC-05 SPP替代。macOS/Linux桌面使用原生串口/演示，各平台构建结论见对应版本CI与Release，不能由网页运行推定真实设备联调通过。

## HC-05类蓝牙链路

桌面直连路径：USB手柄→上位机→Windows RFCOMM/SPP→HC-05 UART→STM32 USART1，无需创建或选择COM。传统SPP传出虚拟COM仍可从原串口入口使用；不能和SPP直连、手机或其他串口程序同时占用模块。传输方式不改变固件协议、UART/DMA外设或500ms失联门禁。

1. **先断动力接线。**模块TX接PA10/RX，模块RX接PA9/TX，GND共地。供电和逻辑电平按具体板卡确认，不把供电电压当UART电平。
2. 模块须双向透明传输二进制，通信模式UART为115200/8N1；AT配置模式波特率不等于透传波特率。RFCOMM无线链路本身不设置UART波特率，本工具不修改模块AT配置。
3. 在Windows设置完成HC-05配对，关闭手机蓝牙串口助手。桌面选“蓝牙SPP直连 · 无需COM”，刷新“已配对的SPP设备”，按名称与MAC明确选HC-05，点“连接蓝牙并握手”；连接中可取消。
4. 刷新仅读本机已配对服务缓存，不扫描、不配对、不自动连接、不猜RFCOMM通道；按SPP服务UUID由Windows解析。没有HC-05时回Windows检查配对与SPP服务，不拿其他SPP设备代替。
5. 分别确认链路打开、固件握手和电机反馈。链路/WSA错误与协议错误分开显示；SPP已连接不代表固件或电机ready。

蓝牙每事务单次400ms、不自动重发整批响应；原COM/网页普通事务150ms且最多一次同字节重试，速度动作都不重试。蓝牙空闲九状态查询最短400ms、详细四轮最短1s；遥控时状态与最新速度交替，详细四轮暂缓。持续合法请求刷新固件计时，空闲100ms才发心跳。连接最多8s、整帧写最多50ms。

400ms是PC等待预算，不是无线实时保证；不能以400<500证明请求始终及时送达。超时会撤销会话、清旧速度/队列并关闭链路，报告序号、操作码、应答数量及缺失设备，迟到响应不恢复许可。250ms输入、600ms底盘反馈/使能确认和下位机500ms保护不变；弱链路应查供电/干扰或改USB，不继续放宽门禁。用户延迟日志、缓存观察和射频验证边界见[VALIDATION](VALIDATION.md)。

## 固定手柄映射

插入USB手柄，进入“手柄遥控”并明确选择设备即可预览，无需填编号或额外应用绑定。页面仅保留设备、前后/左右/旋转三路输入条、Start及必要安全/调度状态；诊断另见下一节。未连串口也可看输入，但预览不是已发送速度、电机反馈或执行确认；未使能时调度目标为零。

| 输入 | Windows WinMM | 浏览器Gamepad API | 动作 |
|---|---|---|---|
| 左杆X | code0 | axes0 | 右推向右平移 |
| 左杆Y | code1 | axes1 | 上推向前 |
| 右杆X | Z/code2 | axes2 | 右推顺时针旋转 |
| 右杆Y | Z旋转/code3，上推值降低 | 不用于控制 | 不参与控制、回中或输入合法性门禁 |
| Start | 按钮10/零基code9 | button9 | 切换遥控许可 |

浏览器其余API通道不宣称等同WinMM。固定控制不提供轴号、按钮号、反向、死区或应用绑定编辑；旧gilrs采集、手动绑定及遥控页重复原始面板已移除。

### 开启、运动与停止

1. 支撑重力负载、架空底盘，确认硬件急停及安全空间。先查询能力：须至少0.4m/s平移、360deg/s旋转和360rpm轮速；旧10deg/s/160rpm固件拒绝开启手柄，须更新匹配固件/上位机，不是只重开旧程序。
2. 三个控制轴回中、稳定释放Start后重新按下，仅请求使能底盘`0x40`；等四轮新反馈确认才允许运动，不使能六台位置DM或两台M2006。
3. Start按下和释放分别须连续稳定40ms，长按只切换一次，10～20ms抖动不重复触发。径向中心死区0.12，死区外线性换算。
4. 平移满幅合成≤0.4m/s，斜推也不超过；旋转满幅±360deg/s（一秒一圈），轮速软件包络360rpm。回中发送零速但保持使能；手动1m/s及组合包络区别见[USAGE](USAGE.md)。360rpm是用户确认的软件上限，不是机械安全保证。
5. 再次有效按下Start无需回中，向全部九个控制单元发失能。全体失能会释放关节/伸缩保持力，不是机械锁定，先支撑机构。

速度使用最新值单槽，最快每100ms发送一次，不积压旧杆位；250ms无新鲜输入退出。遥控与手动共用唯一序号和单在途写口；开启时普通手动动作互斥，安全停机可撤销遥控，停机请求优先。失能需收齐九个不同设备的应答，各台非零故障结果保留，缺失应答不宣称停机成功。

离开遥控页（含进入输入诊断）、失焦/隐藏、断柄、身份变化、无效控制输入或输入超时均撤销许可；恢复不自动运动，重新开启必须稳定释放后再新按。停止保留设备选择，重连/身份变化则清除选择。串口完全故障仍依赖下位机500ms门禁及正常CAN/电调，软件不能替代硬件急停。

## 只读输入诊断：Select / Analog与轴号

在同一`DMDebugStation.exe`打开“输入诊断”。切页会撤销遥控许可，已开启遥控时请求全设备失能，原串口会话可保留。不再单独发布手柄测试EXE；严格独立只读模式运行：

```sh
DMDebugStation.exe --input-diagnostics
```

该模式不注册串口、电机或Ozone控制命令。测试前关闭其他遥控软件、隔离动力；普通浏览器仅显示Windows桌面入口说明，不用旧raw面板冒充WinMM诊断。

1. 确认设备、Windows输入通道及界面显示的日志路径。诊断使用WinMM独立轴，与桌面正式遥控共享采集实现，不经过gilrs标准手柄映射；失焦不暂停采集，日志在独立线程写入，不把文件I/O放进遥控采样路径。
2. “普通模式”逐项慢测：左右杆各四方向、十字键、1～4、肩键、Select、Start和摇杆按下；每个动作后释放回中。
3. 点阶段标记“准备按Analog”，按物理Analog并记录LED变化；点“Analog后重复测试”，再做同套动作。Select另行标记前后，不因按键名推断它是模式键。
4. 与Windows `joy.cpl`的X/Y/Z/Z旋转等通道对照：每轴显示系统校准整数`rawValue`、声明`minimum..maximum`及归一化`value`，不反向、不加软件死区、不按实测端点自动放大。物理按钮仅读位图，POV另列，不把模拟轴解释成扳机。
5. Code是当前API通道号，不是通用物理键位。驱动可能仅提供名称，USB VID/PID和UUID未知时显示“未提供”，不把制造商编号伪当USB身份。无变化的Analog等键可能仅由手柄内部处理，不能仅凭无事件判定损坏。
6. 完整事件自动写入界面所示JSONL日志，可发回分析。页面最多展示最近200条，不等于完整记录；暂停记录不控制设备，继续后不补造暂停期间事件。

WinMM每20ms读取校准快照、记录观察到的变化，不是USB HID报文抓取，不保证记录短于采样周期的按键脉冲。轴归一化仅按系统声明量程线性换算，回中可能有一个整数单位偏差；不能用诊断日志证明电机动作安全。
