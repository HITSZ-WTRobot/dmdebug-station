# Ozone直接内存调参

[文档索引](README.md) · [串口工作台与安全](USAGE.md) · [验证边界](VALIDATION.md)

独立“Ozone调参”页通过桌面TCP后端读写实际控制器RAM，不增加串口操作码、固件暂存区或邮箱。串口工作台的MIT/PID查询仍为只读；两种入口的单位和安全条件不可混用。

## 准备与连接

1. 先确认机械支撑、动力隔离、硬件急停和安全空间。直接内存工具不提供参数物理范围、使能、运动或静止状态门禁，可能立即改变保持力矩和输出限幅。
2. 启动支持Automation Socket的Ozone：接口自V3.40提供，参考工程使用V3.50。连接目标并加载与板上程序匹配、含调试符号的ELF。
3. 使用Windows桌面程序进入“Ozone调参”，连接本机`127.0.0.1:19200`，选择单台DM或M2006并读取参数。普通网页不能建立原始TCP，仅显示桌面入口，不伪造连接或写入成功。
4. CPU是否运行由操作者决定；工具不会烧录、复位、暂停或运行CPU。切换串口/Ozone页保留原通信引擎及500ms失联保护，但该保护不将直接RAM写入变成安全调参接口。

此处操作与历史界面验证来自Windows；不据此宣称macOS/Linux桌面已验证，平台产物见[RELEASE](RELEASE.md)。

## 字段、单位与写入

页面显示实际C++字段表达式、由符号解析出的RAM地址、读回值、独立编辑草稿和单位；各设备草稿隔离，不以串口缓存冒充Ozone读回。

- **DM目录：**MIT/轨迹参数。伸缩此页使用内部输出轴deg、deg/s及对应角度时间单位，与串口工作台的mm不同，不再乘除传动比。
- **M2006目录仅六项：**`velocity_kp`、`velocity_ki`、`velocity_kd`、`velocity_output_max`、`max_rpm`、`stationary_rpm`。PID写实际`controller_.pid_.cfg_`并镜像`config_.velocity_pid`，后两项仅写`config_`、无镜像；没有位置PD、轨迹、finish或optional轨迹对象。
- 不写`config::dm_control`等启动数组。需要保持设备重建时一致的配置副本作为镜像地址逐项写回；重启后RAM修改消失，仍使用固件编译启动值。要持久化启动默认值需另行修改固件源码，本工具不写Flash。

操作顺序：

1. 先读取当前实际值，核对表达式、单位和地址。
2. 明确授权直接写入，编辑一个参数，点击该行写入。写的是活跃控制对象字段及必要镜像，不是只改草稿或启动配置。
3. 软件逐项回读，只有float32位值全部一致才显示成功；单次写入授权自动撤销，切设备或连接状态变化也撤销授权。
4. 调整后再次读取确认。失败/超时立即停止写入，重新连接并读取；不自动重试、回滚或继续假定旧值。

地址由匹配ELF解析，不固定C++类偏移；目录仅开放本工程固定参数，检查RAM、类型、指针和float32有限编码，每次写入重新解析地址。ELF不匹配或对象/成员无法解析即拒绝，不猜偏移。旧M2006位置参数文件/符号不兼容，未知key明确拒绝，不保留兼容假字段。

## 参数文件

- 导出保存当前读到的单台实际参数，不导出未写草稿冒充设备值。
- 导入检查设备及字段格式，只更新草稿，不自动写设备。
- 不自动清PID历史、使能或恢复旧目标；M2006速度目标直接进入PID，没有加减速规划。

## 不可忽略的风险

RAM写入绕过设备接口校验。多地址/镜像写入**不是原子事务**，控制中断可能读到中间值；失败也可能已部分写入，必须重新读取。没有自动回滚或重试，不根据成功提示推断机构安全。

M2006的`max_rpm`调小使现有目标越界时，固件锁存故障并清零，不偷偷钳位。直接改动PID/限幅可能引发即时控制变化；本页不是机械安全工具，暂停CPU或断开TCP也不证明电机已停。

已有本地TCP模拟、历史位置模式字段及当前六字段回归的边界详见[VALIDATION](VALIDATION.md)。尚未连接真实Ozone/J-Link或写真实目标内存；实际Ozone版本符号解析、匹配ELF、运行态访问及实物响应仍需安全条件下确认。
