# DMDebug Station · 三总线设备工作台

组织仓库：[HITSZ-WTRobot/dmdebug-station](https://github.com/HITSZ-WTRobot/dmdebug-station)。项目概览、依赖和源码构建入口见[根目录README](../README.md)；配套下位机为[HITSZ-WTRobot/FDCAN_DM_TEST](https://github.com/HITSZ-WTRobot/FDCAN_DM_TEST)。

桌面版和便携网页使用同一份 React/TypeScript 源码，统一适配下位机 `SERIAL_PROTOCOL.md` **v2**。浅色实验台界面，按 FDCAN 总线分组展示九个控制单元、十二台电机。不自动启动演示、不自动连接串口、不自动使能或恢复旧目标。

## 使用入口

- Windows桌面：根目录 `DMDebugStation.exe`，原生COM串口或“蓝牙SPP直连 · 无需COM”；需要WebView2 Runtime。蓝牙按已配对SPP设备名称/MAC连接，非BLE，不在普通网页提供假直连。
- 免安装网页：直接用当前 Chrome/Edge 打开 `web/index.html` 或 `web/串口.html`，两份文件内容一致，JS/CSS 已内联，不依赖开发服务器、外部字体或 CDN。
- `dist/` 是桌面构建使用的 Web 资源，不是旧 v1 页面。两个便携网页由同一构建自动导出，不再单独维护第二套协议或界面。

原COM/网页串口固定115200/8N1/无流控；桌面可改选蓝牙SPP直连，无需COM。蓝牙无线链路不设置UART波特率，但HC-05模块到STM32必须115200/8N1。普通网页仍用Web Serial授权端口，要求当前Chrome/Edge和Promise.withResolvers；不能调用经典RFCOMM或用Web Bluetooth替代。不要多程序、手机或不同入口同时占用模块。

## 如何确认真正连上

连接显示分三层，不再把“端口打开”显示成“硬件在线”：

1. **端口/蓝牙链路打开**：串口或SPP字节通道已建立，不表示固件ready；动作仍禁止。
2. **固件握手**：已收到合法 v2 心跳、Info 及完整九设备状态；v1 明确显示协议不兼容。
3. **电机反馈**：逐台查看下位机返回的 connected、零点、使能确认、运动/故障及反馈计数；底盘核对四轮在线/使能位图和四轮状态。

端口打开但没有完整应答，会显示“未收到完整应答”，动作禁止；可以明确重新握手或断开。电机状态超过600ms标记过期，不把缓存作为新鲜测量；曲线不采集离线缓存。参数查询更新时间与状态反馈更新时间分开保存。

“协议演示 · 无硬件”必须主动选择并启动，页面顶部持续提示数据来源。它只演示协议和交互，不是电机物理模型、真实 S 曲线、真实电流或带载效果的验证。演示不会自动作为串口失败的后备连接。

## 设备和单位

| 逻辑编号(hex) | 设备 | 位置/控制单位 | 总线 |
|---|---|---|---|
| 0A / 0B / 0C / 0E | 右前 / 中 / 后 / 左前伸缩 | 绝对 mm | FDCAN1 |
| 0D / 0F | 左前 / 右前关节 | 绝对 deg，−180～+180 | FDCAN1 |
| 21 / 22 | 两台独立 M2006/C610 | 输出轴速度rpm，默认−300～+300；位置仅deg诊断 | FDCAN3 |
| 40 | 四轮全向底盘 | vx/vy m/s、wz deg/s | FDCAN2 |

逻辑编号不是全部设备的原始 CAN ID。底盘四轮顺序为右前、左前、左后、右后，对应 CAN 0B/0A/09/0C；四轮状态标签41～44只用于查询，不提供单轮控制。

- 伸缩按226.2mm/输出轴圈换算，不额外计入内置减速；无软件行程min/max。配套固件为±200mm目标将四台位置伸缩PMAX设为125rad，对应协议原点附近±234.34mm，电机端必须支持且同步125。软件零点偏移会改变两侧剩余距离，不能保证任意新零点都可±200mm；实际编码边界仍由固件拒绝，不在上位机截断。底盘轮电机PMAX不随之改动。
- 底盘采用车体系速度，x向前、y向左、wz逆时针；固件/手动控制合成平移≤1m/s、wz≤10deg/s、单轮包络160rpm。手动输入只是草稿，点击“应用速度”才下发；旧固件按真实参数查询保留较低上限。手柄平移另限为0.4m/s，按幅度比例控制，斜推合成也不超过0.4；旋转上限不变。不开放整车位姿或世界系导航。
- M2006改为直接速度PID18/0.1/0、电流协议限幅8000，max_rpm=300、stationary_rpm=0.1；没有位置PD、轨迹或finish。8000约8A转矩电流指令，不是电源输入电流或安全保证。串口参数只读，Ozone显式写实际RAM。Info使用kind5、unit4，Parameters26B，MotorVelocity0x28；旧kind3位置固件不能握手，旧Move/SetZero对M2006返回105，不静默转换。

## 操作顺序

先支撑机构、确认硬件急停和安全空间，再连接、握手、逐台核对反馈。只有六DM需要稳定反馈自动首次归零；M2006无需零点，但必须失能后50个新低速样本才允许明确使能。上电均不自动使能。

1. 选择设备，读取新状态和参数。切换设备只切换观察对象，不销毁通信引擎、不重连或重置演示状态。
2. 确认在线、有效参数、新鲜失能及设备条件后明确使能。M2006必须先查询max_rpm和静止阈值，并由下位机检查50个新低速样本；故障排除后同样显式Enable清锁存，以0rpm重新授权，不恢复旧目标。enabled不是C610物理使能应答。
3. DM输入绝对位置，M2006输入输出轴rpm目标，底盘输入车体系速度；编辑不发送，明确应用才下发。M2006可在运行中更新目标/换向，超限拒绝保留旧值，直接速度阶跃可能有电流冲击；没有“到位”状态，ACK不证明达速。
4. DM“停止/保持”取消轨迹并保持位置；M2006与底盘“零速停止”只设零速度并保持授权，不锁位置。M2006失能清PID和旧目标、电流归零；这些软件操作都不是物理停机或硬件急停证明。
5. “失能”或“全设备失能”发送相应请求，随后查看新反馈。广播逐台返回九帧，允许部分设备返回先前故障结果；不能因一个ACK或断线就宣布全部已停。M2006可已清零电流但仍保留故障原因。

### 先诊断 Select / Analog 与实际轴号

工作台已提供“输入诊断”页，与串口、Ozone调参及精简遥控整合。进入该页会撤销遥控，已开启时请求全设备失能，但不重建串口会话。不再单独发布手柄测试EXE；严格只读诊断可运行 `DMDebugStation.exe --input-diagnostics`，不注册电机控制。测试前关闭其他遥控软件并隔离动力。

新版诊断与桌面正式遥控共享WinMM采集实现，轴、物理按钮和POV分开，可对照 `joy.cpl` 的X/Y/Z/Z旋转，显示Windows整数rawValue、系统量程与归一化value；日志线程独立于遥控采样。诊断不反向、不加死区或自动校准端点，失焦不影响记录。驱动未提供USB身份时显示“未提供”。用阶段标记记录Analog/Select前后与LED变化；完整JSONL自动保存，最近200条仅为显示窗口。20ms快照不是USB报文抓取。普通浏览器不能调用WinMM，显示桌面入口说明，不再提供旧原始面板冒充此诊断。

### 手柄遥控与蓝牙串口

HC-05透传：模块TX→PA10、RX←PA9、共地，供电/电平按板卡确认，模块UART115200/8N1。电脑先完成Windows配对，关闭手机串口助手，再在桌面选“蓝牙SPP直连 · 无需COM”，刷新、明确选HC-05名称/MAC并“连接蓝牙并握手”；连接中可取消。不扫描/配对/自动连接或猜RFCOMM通道，按SPP服务UUID由Windows解析。原COM入口仍可用，不能与直连同时占模块；网页只走Web Serial。保持原DMA、协议及500ms门禁，不修改模块AT或生成外设。

先看“蓝牙链路”，再看“固件握手”和“电机反馈”；蓝牙已打开但无完整协议应答与根本未建立SPP是不同故障，错误含阶段和原生码。建立期限8秒、每帧写期限50ms，旧连接取消后晚到的成功直接释放、不握手、不续跑；原150ms协议期限不放宽、不自动重连或演示回退。没有HC-05选项需回Windows检查配对/SPP服务；其他SPP设备不是机器人。

“手柄遥控”页选择USB手柄即可预览，只保留前后/左右/旋转三路实时输入条、Start状态和必要安全/调度状态，不再填写轴号、按钮号、反向、死区或应用绑定。左杆X/Y=Windows code0/1，右杆X=Z/code2；右杆Y=Z旋转/code3，上推值降低，但不参与控制、回中或校验。Start=按钮10/code9。浏览器使用自身Gamepad API，固定axes0/1/2和button9；其余通道不假定等同WinMM。

Start的按下与释放分别连续稳定40ms才确认，长按不重复切换。初次必须三控制轴回中、稳定释放后新按下才请求Enable0x40；等四轮新反馈确认后才接受速度。第二次有效按下无需回中，发送DisableFF全部九设备。径向死区0.12，手柄平移合成≤0.4m/s、旋转仍≤10deg/s，回中零速不失能。离页/失焦/隐藏、断柄/身份变化或250ms输入租约过期会撤销许可且不自动续跑；停止保留选择，重连须重选。全体失能解除保持力，不是机械锁定，机构须支撑。

遥控和原手动控制共用单在途写口/序号，速度只保留最新杆位、不积压；开启遥控时普通手动动作被互斥，安全停机能撤销遥控。失能需收齐九个不同设备的应答，各台非零故障结果保留显示，不能用按钮状态或ACK证明实物已停。旧低速固件的查询能力不足时拒绝1m/s遥控，必须先更新匹配固件。

桌面Rust唯一actor互斥拥有串口、RFCOMM或演示，协议、心跳/超时/单队列、手柄和停机行为共用；WinMM固定输入和Start消抖不改。React只显示并提交意图，浏览器另保留Web Serial/Worker/Gamepad API，没有经典蓝牙直连能力。三路预览不是发送确认或电机反馈，未使能目标为零。

### 软件零点和运动约束

软件设零仅用于六DM，须失能、连接且静止稳定；确认后当前位置成为新0而非移动，关节重新建立±180°，伸缩重定义毫米原点。成功后作废旧坐标系草稿和曲线；M2006没有设零/0～360°位置工作区，位置仅诊断，不用速度目标叠画位置。

DM运动约束在串口工作台折叠区编辑：伸缩只提交v/a/jerk三个毫米时间单位，关节提交min/max/v/a/jerk五个角度时间单位。该串口命令只在失能时应用，仅RAM生效，不写Flash。伸缩参数返回的min/max NaN显示为无软件行程区间。Ozone功能页是独立的直接内存调试通道，不受这些串口应用条件约束，不增加下位机邮箱。

### 独立Ozone调参页

1. 在Ozone加载匹配板上固件的ELF并连接目标，保持运行状态由操作者决定；本工具不发送暂停、运行、复位、烧录命令。
2. 上位机切换“Ozone调参”，连接TCP127.0.0.1:19200，选择一台DM或M2006，读取实际字段。网页入口无TCP后端，不能写Ozone；使用Windows桌面版。
3. 对照该行的C++表达式、当前值和地址编辑草稿，明确授权后逐行写入。写入控制器正在使用的配置，不写 `config::dm_control` 等启动数组；需要的配置镜像逐项直接写回，全部读回一致才确认。每个设备使用独立草稿，不根据串口缓存冒充Ozone读回。
4. DM目录保持MIT/轨迹参数；M2006只保留velocity_kp/ki/kd/output_max、max_rpm和stationary_rpm。PID写真实controller_.pid_.cfg_并镜像config_.velocity_pid，max_rpm/stationary_rpm无镜像；删除位置PD、轨迹、finish和optional访问。旧文件含未知位置key时拒绝，不保留兼容假字段。
5. 导出的是已读实际值；导入检查设备与字段格式，只填草稿、不自动写入。需要保存启动默认值时仍应另行修改固件源码，本工具不写Flash。
6. 发生失败或超时后停止写入，重新连接并读取；写入可能部分完成，不自动重试/回滚。切设备或连接状态变化会撤销授权，需重新确认。

直接内存调试不检查使能/静止/运动或机械参数范围，不重置PID历史；控制输出可能立即变化，多地址写入不原子。M2006 max_rpm变小导致现有目标越界时，固件锁存故障并清零，而非偷偷钳位。ELF不匹配、对象/成员无法解析即拒绝，不猜偏移；每次写入重新解析RAM地址。

## 曲线、记录和导出

- 位置、速度和DM力矩分开查看，轴单位随设备变化，不把mm与deg或m/s与deg/s混在同一坐标轴。
- M2006默认速度图用输出轴rpm显示实际、目标、PID参考；位置图仅deg诊断，不绘制rpm目标。无电流/力矩公开字段，不伪造测量。CSV按position_deg、velocity_rpm及target_rpm区分单位。
- 底盘平移vx/vy与旋转wz分开选择；四轮反馈单独核对。
- 每设备最多保留1000个实际收到的样本；支持暂停/继续、清空及CSV。暂停图表不停止通讯，暂停期间不补造样本。CSV含逻辑设备编号、时间、单位化列名和demo/hardware来源。
- 通讯记录保留500条，支持TX/RX/异常筛选、原始十六进制展开、暂停滚动和日志导出。日志时间格式器复用，旧日志行和未改变的控制/图表不随每个报文反复重绘。

## 断线和恢复

下位机>=500ms无有效请求会撤销全部设备运行授权，停机帧依赖MCU、CAN和电调。恢复需新序号心跳和严格Info清单；M2006排除故障、失能且50个新低速反馈后显式Enable，以0rpm授权，再明确新目标。不自动续跑或软件设零。断开不等于急停。

事务单在途，FF收齐九设备、Wheels收齐四轮，按sequence/opcode/设备集合匹配。普通事务150ms等待、最多一次原字节重试；BodyVelocity和MotorVelocity不重发旧速度，ACK丢失后明确报失败。耗尽后停止队列并要求人工恢复，不换新序号自动重发运动。

### 串口间歇超时修复

- 早期Web调度修复使用连接专属20ms内联Worker避免Window后台节流；该机制现在仅用于浏览器版。桌面通信的150ms截止时间与心跳轮询已迁至Rust独立线程，不依赖WebView定时器。
- 断开、失败和重新握手会终止旧Worker并释放Blob URL，旧会话回调不再发包；失败后需人工重新握手，不自动重连、使能或恢复旧目标。内联Worker已包含在便携HTML，不依赖额外worker文件。
- 下位机500ms门禁不放宽。整页/主线程冻结、系统休眠、USB断开或真实收发故障仍可能触发停机；此改动仅解决Window后台计时节流这条已验证的软件路径，不宣称电脑能提供硬实时保证。
- 新固件将串口失联原因保留为107，真正CAN反馈离线仍是1。新心跳只解除链路门禁，设备最近结果107和故障仍需按原流程人工处理；CAN反馈计数继续增长时不要据此去调PID。
- Node24运行 `npm test` 可执行8项确定性回归，无新增依赖。覆盖Window计时器不调度、九设备/四轮缺帧、同字节重试、忙时单在途与旧会话隔离。Node的TypeScript参数属性转换使用实验性开关，会打印提示，但不影响打包后的上位机运行。

本轮实际浏览器受控验证（用串口流边界和真实协议编码应答，不接硬件）：将Window计时器限制为至少1000ms，修复前最大请求间隔1002.1ms，修复后126ms、54个状态应答无故障。另已构建网页/Windows程序，并以file://打开便携HTML完成演示握手、持续收发和零CRC/超时检查；不等同于真实USB-UART或电机实板联调。

本轮已实际启动新生成的Windows桌面程序，观察到原生串口枚举、默认未连接与动作禁用；未打开任何真实COM端口。便携页演示运行期间CRC/超时保持0。系统休眠或主线程完全冻结仍须由下位机门禁停机，现场间歇故障是否消失仍需安全条件下复测。

## 源码、构建和Git

环境：当前Node.js、npm、Rust/Tauri v2和Windows WebView2；依赖版本由package-lock.json/Cargo.lock记录。

```sh
npm install
npm run dev
npm run build:web
npm run build:all
```

- build:web执行TypeScript检查、Vite构建和便携网页导出。
- build:all通过Tauri构建执行同一前端流程，再将当前release程序复制到根目录DMDebugStation.exe；不能只改源码后继续运行旧exe。
- Git保留现有基线、工作台与串口修复提交；首次发布以最新修复版初始化组织仓库 `HITSZ-WTRobot/dmdebug-station` 的main，并保留已有开发分支。后续从main创建功能/修复分支并通过PR合入，不强推或重写历史。node_modules、dist、Rust target和exe等产物忽略，两个便携web入口随源码更新。不要只更新源码后继续使用旧exe或旧HTML。
- 业务接口/编解码在src/lib，状态契约在src/store，设备控制/遥测/日志行是独立组件。两种交付不再维护重复的v1协议逻辑。
